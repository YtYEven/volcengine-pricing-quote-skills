# 云迁移对标报价

## 适用场景

用户提出以下类型的请求时调用此 skill：
- "客户给了一份阿里云清单，帮我做火山的对标报价"
- "把这份 xxx 客户的资源清单做迁移报价"
- "客户要 N 台 ECS、规格 xxx，给个火山报价单"
- "重做一份给 XX 客户的报价 Excel"

## 模式区分

### 模式 1：友商清单 → 对标报价（云迁移场景）
- 输入：阿里云/腾讯云/AWS 资源清单（CSV / Excel / 账单截图 / Markdown）。
- 处理：阿里产品 → 火山产品对标 → 规格映射 → 取价 → 多 sheet Excel。
- 输出 Excel 包含"产品对照表"sheet（场景 1 专属）+ 各分类报价 sheet。

### 模式 2：直接需求 → 报价单（非迁移）
- 输入：客户自然语言描述（"8 台 4C8G ECS、1 台 RDS MySQL 8C32G 500G"）。
- 处理：直接做规格匹配 + 取价。
- 输出 Excel **去掉"产品对照表"sheet 与"阿里产品/阿里规格"两列**，其余结构相同。

## 核心约束（永远不要违反）

来自用户的强约束：
1. **不计算成本/金钱**，优先保证报价单的**正确性、可读性、可追溯性**。
2. **缺规格的产品必须做经验假设**并在备注列明文写出，绝不黑盒拍。
3. **无对标产品** → 写"待补"并在备注列给 2~3 个候选火山产品供客户选择（不要硬塞一个数字进总价）。
4. **不列阿里云价格**（场景 1 也只列阿里产品+规格做溯源，不抄阿里报价）。
5. **隐藏成本默认不计**（公网带宽、镜像授权、备份、跨区流量等），在对应行的备注列写明"未计入"。

## 标准执行流程

### Step 1 — 解析输入
- 模式 1：读取友商清单文件。允许格式：CSV、xlsx、Markdown 表格、直接粘贴文本。识别列：产品名 / 规格 / 数量 / 计费方式（若有）。
- 模式 2：从自然语言抽取每个需求项。

### Step 2 — 产品对标
- 查 [product_mapping.md](product_mapping.md) 找已知映射。
- 不在对照表里的产品：访问火山引擎 https://www.volcengine.com/product 与友商官网文档现场对标。
- 无对标 / 功能差异大：在产品对照表 sheet 的"是否完全等价"列标记，并在后续报价 sheet 中给出 2~3 个候选。

### Step 3 — 规格映射
- ECS / RDS / 数据库类：按 [spec_mapping_rules.md](spec_mapping_rules.md) 的"vCPU/内存对齐 + 存储对齐 + 默认 4 代 Intel"规则。
- 其他产品：按各自规则（流量类按 Mbps、套餐类按版本/域名数）。
- **缺规格**：按 [spec_mapping_rules.md](spec_mapping_rules.md) 的"经验默认值"段落取假设，并在备注列写"假设：xxx，待客户确认"。

### Step 4 — 取价
- 数据源：`../火山产品刊例价/*.csv`。
- 取价策略详见 [pricing_lookup.md](pricing_lookup.md)。
- 包1年单价折月 = 包1年总价 / 12（在 Excel cell 里写公式）。

### Step 5 — 确认 sheet 策略
按 [sheet_strategies.md](sheet_strategies.md) 自动推荐策略 A/B/C 之一,并通过**向用户提单选确认问题的能力**跟用户确认 sheet 结构后再生成。

判定逻辑：
- 报价产品涉及 ≤ 10 个 → 推荐 A（极简）
- 11~25 个 → 推荐 B（按结构，**默认**）
- 25+ 个 或 涉及 5+ 个产品大类 → 推荐 C（按类别）
- 用户明说要某一种 → 用指定的

### Step 6 — 生成 Excel
- 用 **Excel 写入库**(推荐 Python `openpyxl`,或同等支持公式与多 sheet 的库)生成多 sheet xlsx。
- 字段顺序统一（详见 [excel_template.md](excel_template.md)）：
  - 实例+存储二元类：`阿里产品 | 阿里规格 | 类别 | 火山产品 | 火山规格 | 配置说明 | 实例月单价 | 存储月单价 | 单台月价 | 数量 | 月总价 | 计费周期 | 周期总价 | 地域 | 备注`
  - 单存储类：`阿里产品 | 阿里规格 | 火山产品 | 存储类型 | 容量 | 容量单价 | 月总价 | 计费周期 | 周期总价 | 地域 | 备注`
  - 网络/安全类：`阿里产品 | 阿里规格 | 火山产品 | 规格/套餐 | 月单价 | 数量 | 月总价 | 计费周期 | 周期总价 | 地域 | 备注`
  - 按量计费类：`阿里产品 | 阿里规格 | 火山产品 | 火山规格 | 计费维度 | 单价 | 单位 | 估算说明 | 地域 | 备注`
- 派生列必须用公式：`单台月价 = 实例月单价 + 存储月单价`、`月总价 = 单台月价 × 数量`、`周期总价 = 月总价 × 周期月数`。
- 每个数据 sheet 底部加一行**合计**（数量列 SUM、月总价 SUM、周期总价 SUM）。
- 必须有 **"假设与说明"** sheet：列出地域默认、代次默认、缺规格的假设、无对标的产品、未计入的隐藏成本。
- **品牌分区配色**(详见 [excel_template.md](excel_template.md) 第六章):所有 sheet 的列自动按 `classify_column(header)` 分到 阿里(暖橙)/火山(冷蓝)/中性(灰) 三色系,表头深色白字、数据浅色、合计中色加粗。场景 2 自动跳过 ali 列。**不要**手工逐 cell 调色。

### Step 7 — 输出与验收
- 文件命名:`<客户名>-火山引擎报价-YYYYMMDD.xlsx`,放到客户目录或当前工作目录。
- **跑验收脚本**:`python3 scripts/verify_quote.py <文件路径> --strategy <A|B|C> --scenario <1|2>` —— 必须 ✅ 通过(0 errors)才算完成。
  - 若 FAIL,定位错误(常见:派生列被填了死值、合计行缺 SUM、sheet 数与策略不符),修复后重生成,**不要**带 fail 交付。
- 向用户汇报:列出 N 个产品已精算、N 个已假设规格、N 个无对标待补,附 Excel 路径和验收脚本输出。

## 默认值（用户没指定时统一用这些）

| 项 | 默认 |
| --- | --- |
| 地域 | 华东2（上海） |
| 计费方式 | 包1年（除非客户标按量 或 火山产品仅按量计费） |
| ECS 代次/芯片 | 最新代次 + Intel（g4i / c4i / r4i） |
| 系统盘类型 | 极速型 SSD PL0（0.5 元/GiB/月） |
| 数据盘类型 | 极速型 SSD FlexPL（1.0 元/GiB/月） |
| 包1年月折算 | 包1年总价 / 12 |
| 隐藏成本 | 不计入，备注里写明 |

## 验收标准

- [ ] 输入清单中每个产品都在 Excel 里能找到（无遗漏）。
- [ ] 每个总价格都用 Excel 公式串起来，可点击 cell 看到来源。
- [ ] 缺规格的行有明文假设。
- [ ] 无对标的行有 2~3 个候选说明。
- [ ] "假设与说明"sheet 列全。
- [ ] 合计行金额 = 上方行 SUM。
- [ ] 至少一次**单选确认问题**让用户确认 sheet 策略后再生成。

> 工具名提示(Claude Code 环境):单选确认=`AskUserQuestion`;Excel 写入=Python `openpyxl`;文件读=`Read`/`Write`/`Edit`。换运行时按各自能力替换。
